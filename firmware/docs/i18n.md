# UI strings

Lexipoint's UI is in English only: v0.2 V8 removed CrossPoint's 33 other UI languages, the Language screen and the
keyboard layouts that followed the UI language (`../../docs/v0.2/slimming.md` §8). The string machinery stays, so
every user-facing string still has one home and goes through `tr()`.

## Where strings live

```
lib/I18n/
├── translations/english.yaml   # every STR_* key and its text
├── I18n.h / I18n.cpp           # the I18n class and tr()
├── I18nKeys.h                  # generated: the StrId enum
├── I18nStrings.h / .cpp        # generated: the string table
scripts/gen_i18n.py             # the generator (a pre: script of every build)
```

The three generated files are gitignored and made at build time. One language table remains (English's blob and
offsets, `STRINGS_EN_DATA` / `OFFSETS_EN`): `I18n::get` reads it directly, with no current language or per-language
lookup (V8 R8).

## Adding a string

1. Add the key to `lib/I18n/translations/english.yaml`:

   ```yaml
   STR_MY_NEW_STRING: "My New String"
   ```

2. Run the generator (the build does it too):

   ```bash
   python3 scripts/gen_i18n.py lib/I18n/translations lib/I18n/
   ```

   It reports keys no code uses; delete those from the YAML.

3. Use it:

   ```cpp
   #include <I18n.h>

   renderer.drawText(font, x, y, tr(STR_MY_NEW_STRING));
   ```

The file format is `STR_KEY: "text"` per line (`\\`, `\"` and `\n` are the only escapes), after four header lines
(`_language_name`, `_language_code`, `_order`, `_bcp47`) that the generator still reads. The generator rejects
comments in the file.
